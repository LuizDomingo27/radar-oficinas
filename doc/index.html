Referência de manutenção

Como o Radar de Oficinas transforma planilhas em números.

O que o app faz, quais planilhas ele lê, quais colunas alimentam cada métrica e de onde vem cada valor — para dar manutenção e validar os resultados célula a célula.

Interface · Streamlit + ECharts ETL · Python / openpyxl Config · app_oficinas/config.py

Visão geral

01

O Radar mede o desempenho das oficinas parceiras e cruza esse desempenho com os treinamentos que elas receberam.

A partir de planilhas .xlsx exportadas pela operação, um pipeline em Python gera arquivos data/*.json que abastecem um painel web com quatro telas:

  • Ranking geral — oficinas comparadas por peças/mês, peças/semana, totais recentes, absenteísmo e eficiência.
  • Ficha da oficina — linha do tempo de produção e absenteísmo, a % de eficiência atual e os marcos de treino.
  • Impacto — antes × depois do treino, com grupo de controle (diferença-em-diferenças).
  • Qualidade — nota de qualidade, índice de 2ª qualidade e as principais causas de defeito.
Princípio central: o app não inventa fórmula. Ele lê os números que as próprias planilhas já calculam (eficiência, qualidade) e apenas agrega/organiza. Onde há cálculo, reproduz o critério da planilha de origem.

Pipeline de dados

02

O comando python -m scripts.build_tudo (o que o botão Atualizar dados dispara) roda seis passos em ordem — cada um lê a saída do anterior.

#PassoScriptO que fazGera
1De-Parabuild_depara.pyNormaliza a razão social e cria a dimensão canônica de oficinas.depara.json
2Fatos (ETL)build_fatos.pyLê as colunas de valor e resolve cada linha à oficina canônica.fato_*.json
3Métricasbuild_metricas.pyAgrega os fatos por oficina × período (mês/semana/ano).metricas_*.json
4Impactobuild_impacto.pyCalcula antes×depois do treino + controle (dif-em-dif).impacto_*.json
5Dashboardbuild_dashboard.pyMonta o payload das telas (ranking, séries, semáforos).dashboard.json
6Qualidadebuild_qualidade.pyLê RESUMO/DEFEITOS do “Indicador geral” e gera a qualidade.qualidade.json
Camadas: infra/ só faz I/O; services/ tem as regras puras; scripts/ orquestra. Toda peculiaridade de planilha (arquivo, aba, linha, coluna) mora em app_oficinas/config.py.

Chave de junção — o De-Para

03

Não existe um código único de oficina compartilhado entre as planilhas. A chave que liga tudo é a razão social, grafada de formas diferentes em cada arquivo (sufixos POLO/CARGO, acentos, ME/LTDA, matriz/filial). Por isso o passo 1 constrói um De-Para:

  • Remove tokens jurídicos (LTDA, ME, EPP…) e de unidade (POLO, CARGO, JEANS, MALHA…) para achar um nome-base.
  • Agrupa variantes no mesmo oficina_id canônico.
  • O nome de exibição segue a grafia de postos.xlsx (lista oficial de parceiros).
  • Nomes muito parecidos (similaridade ≥ 0,90) são marcados para revisão humana.
CNPJ só existe nas planilhas de treinamento; as de desempenho têm apenas o nome. Se uma oficina não cruzar, quase sempre é divergência de razão social — ajuste o vocabulário em config.py (TOKENS_UNIDADE, TOKENS_JURIDICOS, RUIDO).

4.1 · Produtividade — volume de peças

Fonte: RECEBIMENTO.xlsx · aba RECEBIMENTO · dados a partir da linha 2 (diário, jan→ago/2026).

ColunaÍndiceCampoUso
A0Datadefine mês / semana ISO
B1Razão socialchave da oficina
D3MP (matéria-prima)normalização (JEANS/MALHA…)
E4REAL CORTADOpeças produzidas (o volume)
F5MINUTOSbase do antigo peças/minuto (não exibido)
peças/mês (pecas_mes) = média das peças (Σ REAL CORTADO) por mês com dado
peças/semana (pecas_semana) = média das peças por semana ISO com dado
total do mês (pecas_mes_total) = Σ peças do mês mais recente com produção
total da semana (pecas_semana_total) = Σ peças da semana mais recente com produção
# peças_por_minuto = Σpeças ÷ Σminutos — ainda calculado, mas NÃO exibido
Produtividade é lida como volume, não peças/hora. Volume depende do tamanho da oficina, então não tem semáforo. Os “totais” refletem o ritmo atual (último período com dado), não o acumulado do ano.

4.3 · Eficiência

Fonte: duas planilhas de estoque. O valor é a % oficial que a própria planilha calcula — lido direto, sem recalcular.

JEANS

ESTOQUE OFICINAS - JEANS - 2026.xlsx · aba ESTOQUE · cabeçalho 5 · dados 6.

Nome: A (0). Valor: coluna com rótulo % 4WK.

NÃO-JEANS

ESTOQUE OFICINA NÃO JEANS.xlsx · aba ESTOQUE OFICINAS · cabeçalho 8 · dados 9.

MP: A (0). Nome: B (1). Valor: rótulo MÉDIA 4W.

eficiência = Méd. das últimas 4 semanas de entrega (peças) ÷ Cap Peças 100% # já pronta na planilha
A coluna do valor é achada pelo RÓTULO do cabeçalho, não por posição fixa (ROTULOS_EFIC_OFICIAL = "% 4WK", "MÉDIA 4W"). As abas ganham colunas de semana a cada carga. Se o rótulo sumir, o leitor levanta FonteInvalida (falha alto). Não recalcular, não usar base 70%, não usar a aba HISTÓRICO EFIC (abandonada).
Validação célula-a-célula (conferido): IDEAL 0,1816 · I M 0,7921 · ASA 0,5523. Meta = 65%.

Nota de Qualidade = 0,6·%Reprovado + 0,3·%Concessão + 0,1·(Σ2QA ÷ ΣProd) # MAIOR = PIOR
Índice de 2ª Qualidade = Σ2QA ÷ ΣProd

Status no denominador da nota: APROVADO, REPROVADO, APROVADO COM CONCESSÃO (os demais são ignorados). Rankings exigem no mínimo 10 inspeções por oficina. Pesos/filtros em config.py (PESO_*, CAUSAS_*).

4.6 · Impacto do treinamento (dif-em-dif)

Responde: a oficina que treinou melhorou? Compara a métrica antes × depois do treino e contrasta com um grupo de controle de oficinas não treinadas no mesmo período.

pré = anos com dado antes do ano do treino
pós = anos com dado depois do ano do treino # o ano do treino é buffer, excluído
Δ = valor_pós − valor_pré
dif-em-dif = Δmédio(treinadas) − Δmédio(controle)
Cobertura curta hoje (produtividade e eficiência só têm 2026), então a maioria dos pares fica sem janela pré/pós completa — recebe status sem_pre/sem_pos/sem_dado em vez de ser omitida. A máquina fica pronta e preenche conforme o histórico cresce.

Como atualizar os dados

07

Duas formas, ambas rodam o mesmo pipeline (build_tudo):

a) Pelo app (equipe)

  • Barra lateral → Atualizar dados → suba a(s) planilha(s) .xlsx → clique no botão.
  • O app salva os arquivos, roda o build e faz commit dos JSONs no GitHub (o disco do Streamlit Cloud é efêmero).
  • O commit exige o token nos Secrets ([github]) com permissão Contents: Read and write. Sem ela, o app avisa em amarelo que atualizou na sessão mas não persistiu.

b) Pela linha de comando

python -m scripts.build_tudo # regenera todos os data/*.json
python -m http.server 8756 # e abra /web/ para conferir localmente
Mantenha os nomes dos arquivos idênticos aos de config.py. A planilha de qualidade é reconhecida por conter “indicador” no nome.

Como validar um valor

08
  1. Identifique a métrica e ache a oficina no painel.
  2. Volte à planilha/aba/coluna da seção 4 correspondente.
  3. Aplique a fórmula daquela seção sobre as células de origem.
  4. Compare. Exemplos conferidos: eficiência IDEAL 0,1816, I M 0,7921, ASA 0,5523.
Para depurar, os arquivos intermediários ajudam: fato_*.json mostra o dado cru já resolvido à oficina; metricas_*.json mostra a agregação por período — dá para rastrear um número do painel até a linha da planilha.

Notas de manutenção

09
  • Fonte-verdade de configuração: app_oficinas/config.py. Qualquer mudança de arquivo/aba/coluna começa aí.
  • Eficiência é localizada por rótulo de cabeçalho — se renomearem a coluna, atualize ROTULOS_EFIC_OFICIAL. O sistema falha alto em vez de ler errado.
  • “Indicador geral” só entra na Qualidade.
  • Divergência de oficina → confira fatos_nao_resolvidos.json e ajuste o vocabulário em config.py.
  • Streamlit Cloud tem disco efêmero: a persistência real vem do commit dos JSONs no GitHub; o app reimplanta a cada push.
  • Esta documentação é mantida à mão — atualize-a quando colunas ou fórmulas mudarem.
